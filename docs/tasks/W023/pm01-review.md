方案基线为 `14cf5deea749d3a734c596a4d707fdb4cf6775ca`。W018 对合法有理数求首轨中心，其派生分子、分母均可能超过输入的十进制位数。方案可实施。把新写快照的坐标放入版本化编码，在读回时恢复原逻辑类型；编码须区分符号、相近值和字段类型。历史快照及 W006 记录按原字节重编码，保住原内容引用。复核以默认解释器的真实文件发布、读回和精确值为准。[PM 的原始反例](pm01_coordinates.py) · [W018 数值合同](../../../tests/unit/test_w018_model.py)

## 独立样本与判据

在同一临时 W003/W004 样本副本中，保留原 target、物理版图和 W022 坐标的其余 14 层。给无本地图形的 BTAP_P 选 X 向一维轨，节距 7 nm，闭区间 [−2,4]。令 `d = 2**7500`，下边缘为 `(1-d)/d` nm，两次发布的宽度分别为 `2/(d+1)` 与 `2/(d+3)` nm。每次修改后按实际文件重绑 query header，以相同 run ID 和 lineage 在两个空仓库分别初始化第 0 版。

首轨编号为 −2。对 `k ∈ {1, 3}`，由单个分式 `((1-d)*(d+k)+d)/(d*(d+k))` 独立求精确中心。两者都在 −1 nm 上方，差值恰为 `2/((d+1)*(d+3))` nm，转为双精度数均得到 −1。分别核对发布后实际 numerator 和 denominator，并要求坐标模型 ID 及精确分数不同。核模型时读取实际 bundle 和六个 owner 的 SHA-256，通过 W008 取得已经认证的单位引用，按 W018 模型格式独立解析全部层的工艺轴，计算预期 ID。探针不调用 W018 的坐标模型构建器计算期望值。

在装好项目依赖的仓库根目录，使用带整数安全上限的默认 CPython 执行。配置值、首轨索引、模型 ID、快照 0、封存阶段、312 个占用片段和 `encode_record → decode_record` 往返均有断言。[独立探针](pm01_review_probe.py)
