## 2026-05-13 — Correctness audit: input-side schematic / GDS / Calibre-query review (docs only)

**Branch:** `claude/fix-circuit-design-issues-xGyMX`

Adds `docs/correctness_audit.md`, a standing input-side correctness review of the schematic, GDS, layer-map, and Calibre-query fixtures and formats. The audit was prompted by two concrete suspicions: (1) the project is branded "Buffer Fin Resize MVP" but the fixture circuit is a single CMOS inverter (`MN0` + `MP0` with both gates → `IN`, both drains → `OUT`); (2) some dummy-fixture coordinates may have been generated by hand rather than by the parametric generator. After review, the user chose **document only, no code change** for this round; every "Recommendation" in the audit is deferred and tracked in `backlog.md` § "Correctness issues found in audit (2026-05-13)".

Headline findings (full evidence + per-finding fix recommendation in the audit doc):

- **A1** — "buffer" is a misnomer; the fixture is one inverter (cell name `INV_N5_P7` and `generate_inverter_layout()` already correct; the mislabels live in file names, `BUFFER_LIB`, README, `architecture.md` §1, and the M0 changelog entry).
- **C1–C4** — the fixture is **not DRC-clean against its own `drc_rules.yaml`**: `LI.P.1` (27) < `LI.W.1` + `LI.S.1` (34) → 10 nm LI-LI gap on adjacent tracks (two real `LI.S.1` violations); VIA0 has 0 nm LI X-enclosure on all 4 vias (`V0.E.LI.x`); LI does not fully cover VIA0 in Y on 3 of 4 vias (3–4 nm overhang — the `gen_buffer_layout.py:244-262` extend-LI-for-via code omits `VIA0_HEIGHT/2`); VIA0 is under-enclosed by M1 in X on the 2 signal vias (1–2 nm vs 5 nm). These are hidden because CSP only enforces a subset and KLayout DRC is optional.
- **B1** — odd-width shapes (FIN/LI/VIA0 = 7/17/17 nm) plus `int()` truncation at `gen_buffer_layout.py:80-85` produce shapes 0.5 nm off-centre — the "tell" of script-generated rather than tool-generated coords.
- **D1 / D2** — `calibre_device_query.json` and `device_info_*.txt` disagree by 0.5 nm on the same device bbox (`//2` vs `/2` rounding); the `DEVICE INFO` "seed shape" is a synthetic `POLY_W × (fin_span + pitch)` rectangle, not the `POLY ∩ OD` device-recognition geometry a real Calibre would emit (overhangs OD by 2.5 nm/side).
- **E1** — confirmed-via-regen: `python3 dummy/gen_buffer_layout.py` immediately reorders `buffer_original.json` and `calibre_net_query.json` (shape-block ordering only — coord values match) and rewrites `buffer_original.gds` by 2 bytes (gdstk-vs-manual-writer encoding). The committed fixtures have drifted from the generator over time; the fix is to regenerate + re-commit (with gdstk installed) plus a CI guard.
- **E2** — `gen_buffer_layout.py` requires `gdstk` to fully regenerate (the `bbox_by_layer.json` round-trip path), even though `README.md:90-91` calls gdstk "optional". The full regen aborts with `ImportError` without it.

Positive findings called out explicitly so the audit reads fairly: GDS ↔ `bbox_by_layer.json` ↔ `device_info_*.txt` ↔ `net_shapes_*.txt` are mutually consistent (everything flows from `generate_inverter_layout()`); `M1.P/W/S` is self-consistent (20 + 16 = 36); `POLY.X.OD` / `NWELL.X.FIN` / `BOUNDARY.X.FIN` all hold exactly; `iXref` / `nXref` / `NET NAMES` content is internally correct; CDL pin ordering matches the device pins dict.

Out-of-scope follow-ups identified but not done: the resize **output** path (`core/solver.py`, `core/decoder.py`, `core/drc_derivator.py`, `output/buffer_resized.*`); validating the LVS / Calibre HDB formats against a real `calibre` binary; promoting `V0.E.LI` / `V0.E.M1` from KLayout-only to CSP-enforced.

**Files touched.** New `docs/correctness_audit.md`. Edited `docs/README.md` (index + "where to start" pointer), `docs/backlog.md` (new "Correctness issues found in audit (2026-05-13)" subsection under "Cross-cutting deferrals"), `docs/changelog.md` (this entry).

**Acceptance.** Docs only. No code, fixture, golden, or test was changed; no test-count delta. The audit's coordinate arithmetic is reproducible from `tech/drc_rules.yaml` + `tech/layer_map.yaml` + the cited lines of `dummy/gen_buffer_layout.py`, and every cited fixture value is verbatim from the committed file. The E1 drift was confirmed by running `python3 dummy/gen_buffer_layout.py` and inspecting `git diff --stat dummy/fixtures/`; the modified fixtures were then `git checkout`-restored (no fixture change shipped).

**Notes.** This audit deliberately scopes to inputs + formats per the user's choice. The output-path audit is the obvious next pass and would re-check whether C1–C4 recur or worsen after a resize (the resize uses its own LI/M1 reshaping logic in `core/solver.py::_emit_*`, not the buggy via-coverage code in `gen_buffer_layout.py`).

## 2026-05-07 — Stage 1.5 extended: NET SHAPES (M7 seam, fourth slice)

**Branch:** `claude/refine-test-fixtures-nIkdZ`

Adds the per-net `NET SHAPES <lvs_name>` Calibre HDB query — the fourth query in Stage 1.5 — and produces `output/net_shapes.yaml`, a per-net middle file recording every metal/via shape attached to a given net's lvs_index. Joined with the prior net_xref middle file: each entry carries `{lvs_index, lvs_name, schematic_name, layers}`.

`NET SHAPES` is per-net (one subprocess per query). The query argument is the LVS-side net name from NET NAMES — top-level pins keep their schematic strings (`VDD`, `OUT`, …); LVS-renumbered internal nets surface as numeric strings (the user's BUFLVT example uses `NET SHAPES 2` for the renumbered `net9`). Layer names match GDS layer names directly (LI, VIA0, M1) and bbox represents the *effective* conducting region per the user's spec — cuts and extension margins are excluded; layer-name mapping and trimming convention will be tightened in 1.6.

Like DEVICE INFO, the response is stdout-only — Calibre never writes a file — so the runner captures stdout, slices the bounded `Net_Shapes ... END OF RESPONSE` block via `_extract_net_shapes_block`, and persists it as `output/net_shapes_<lvs_name>.txt`. Vertex coordinates land as `<y> <x>` integer pairs in `1 / precision` µm.

- **`io_adapters/calibre_query.py`** — five new functions:
  - `parse_net_shapes` — anchors on `Net_Shapes <precision>` + `Info:` + count line + n_metadata block (last line = first layer name). Walks the post-metadata block parsing `p` shape headers / count lines (skipped) / bare layer-name strings. Terminator-required (raises `ValueError` if EOF without `END OF RESPONSE`).
  - `write_net_shapes_yaml` — serialises only `lvs_index`, `lvs_name`, `schematic_name`, and per-layer `{name, shapes: [{bbox_um}]}`; vertex tuples and opaque metadata stay in memory.
  - `run_calibre_net_shapes` — `calibre -query` subprocess; stdin `NET SHAPES <lvs_name>\nEXIT\n`; same diagnostics as DEVICE INFO. The runner forwards `lvs_name` verbatim, so numeric LVS names (the renumbered case) work without special handling.
  - `run_dummy_net_shapes` — copies a per-net `dummy/fixtures/net_shapes_<lvs_name>.txt`.
  - `extract_net_shapes` — top-level orchestrator: iterates `nets` (typed as the parsed net_xref `nets` list), dispatches one query per net, joins each parsed result with `lvs_index/lvs_name/schematic_name` from the input.
- **New `dummy/fixtures/net_shapes_{IN,OUT,VSS,VDD}.txt`** — auto-generated from `generate_calibre_net_shapes`, sourced from `layout_data['shapes'][layer]` filtered by net + `NET_SHAPES_LAYERS = ['LI', 'VIA0', 'M1']`. Each file mirrors the inverter's actual layer/shape composition (e.g. OUT has 2 LI bars + 1 VIA0 + 1 M1; VDD M1 spans the full cell width 0.0 → 0.108 µm).
- **New `dummy/fixtures/net_shapes.yaml`** — committed parsed reference for byte-comparison in tests.
- **`dummy/gen_buffer_layout.py`** — `generate_calibre_net_shapes(layout_data, lvs_name, filename)` reproduces each per-net fixture from the inverter layout dict; `NET_SHAPES_LAYERS` constant lifts the layer list. Wired into `generate_all_fixtures` to emit one file per net.
- **`tech/site_config.yaml`** — adds `calibre.{net_shapes_dir, dummy_net_shapes_dir}` and `inputs.net_shapes_yaml`.
- **`tech/config_loader.py`** — resolves the two new path-valued fields under `calibre:`.
- **`pipeline/run_mvp.py`** — Stage 1.5 now also runs `extract_net_shapes` after device_info (driven by `parsed_net_xref['nets']`); banner adds `NetShapes: nets=N  layers=N  shapes=N`; legacy site_configs without `calibre.dummy_net_shapes_dir` get the same repo-default fallback (`dummy/fixtures/`).

Adds the per-device `DEVICE INFO <layout_inst>` Calibre HDB query — the third query in Stage 1.5 — and produces an `output/device_info.yaml` middle file that records, per layout instance, the seed-shape bbox of every LVS-derived layer attached to that device.

`DEVICE INFO` is invoked once per device, with `<layout_inst>` taken from the parsed iXref (`devices[*].layout_inst`, e.g. `M0`, `M1`). The response is stdout-only — Calibre never writes a file — so the runner captures stdout and slices the bounded `Device_Info ... END OF RESPONSE` block via `_extract_device_info_block`. Vertex coordinates land as `<y> <x>` integer pairs in `1 / precision` micrometres (precision=20000 → 1 unit = 0.05 nm); the middle file converts them to a `bbox_um` dict per shape.

- **`io_adapters/calibre_query.py`** — five new functions:
  - `parse_device_info` — locates `Device_Info <precision>` header, the `Info:` anchor, the `0 0 <n> <date>` count line; reads `n` opaque metadata lines (the first is `device_type_number`, the last is the seed layer name; pin nets and property values in between are preserved as raw strings since per-device-type counts vary). Walks the post-metadata block parsing `p <idx> <nvert>` shape headers, count lines (skipped), and bare layer-name strings (start a new layer). Robust against the `1 1 0 <date>` vs `<count> 0 <date>` count-line ambiguity in the manual.

  - `run_dummy_device_info` — copies a per-instance `dummy/fixtures/device_info_<inst>.txt`.
  - `extract_device_info` — top-level orchestrator: iterates `layout_insts`, dispatches one query per device, returns `{devices: [...]}`.

## 2026-05-06 — Config consolidation (PR #19)

**Branch:** `claude/consolidate-config-parameters-0WrRX`

Restructured the parameter sources so production testing only needs to edit one path-only YAML. Three composable files now describe the bundle:

- **`tech/drc_rules.yaml`** rewritten in unified rule-record format. ASAP7-style ids (`FIN.P.1`, `V0.E.LI`, `NWELL.X.FIN`, etc.); pitch / width / spacing / enclosure / extension / exact_size are all expressed as one-rule-per-record entries with `layers: [...]` + `value_nm` (scalar or `{x, y}`) + `severity`. Easier to machine-parse from a foundry DRM later.
